# Lecture 05 — Exploratory Data Analysis

### ข้อ 11 — [Lect 05] — Fence ต่างจาก Whisker อย่างไร

**โจทย์:** นักเรียนกำลังอธิบาย Boxplot ของชุดข้อมูลยอดใช้จ่ายต่อเดือน และสังเกตว่าปลายเส้น Whisker
ไม่ไปถึงตำแหน่งของ Fence เลย ข้อความใดอธิบายถูกต้องที่สุดตามหลักในสไลด์

**ตัวเลือก**
- ก) Whisker ต้องยาวไปถึง Fence เสมอ เพราะ Fence คือปลายสุดของการกระจายข้อมูล
- ข) Fence เป็นเกณฑ์ที่คำนวณไว้ ส่วน Whisker สิ้นสุดที่ค่าจริงสุดท้ายซึ่งยังอยู่ภายใน Fence จึงอาจสั้นกว่าระยะถึง Fence
- ค) ค่าใดก็ตามที่อยู่ระหว่างปลาย Whisker กับ Fence ต้องถูกจัดเป็น Outlier
- ง) Fence คือค่าจริงที่พบในข้อมูล ส่วน Whisker คือค่าที่ได้จากการคำนวณ

**เฉลย:** ข) Fence เป็นเกณฑ์ที่คำนวณไว้ ส่วน Whisker สิ้นสุดที่ค่าจริงสุดท้ายซึ่งยังอยู่ภายใน Fence

**วิธีทำ**
1. สไลด์ 17 เขียนไว้ตรง ๆ ว่า *"Fence เป็นเกณฑ์ ส่วน Whisker สิ้นสุดที่ค่าจริงสุดท้ายซึ่งยังอยู่ภายใน Fence"*
2. แยกสองคำนี้ให้ชัด
   - **Fence = เกณฑ์** คำนวณได้จากควอร์ไทล์และ IQR เป็นเส้นสมมติ ไม่จำเป็นต้องมีค่าจริงใดตรงกับเส้นนั้นเลย
   - **Whisker = ปลายของค่าจริง** จบที่ค่าที่ไกลออกไปที่สุดเท่าที่ยังไม่เกิน Fence
3. ผลที่ตามมา: ระยะจากปลายกล่องไปยังปลาย Whisker **สั้นกว่าหรือเท่ากับ** ระยะจากปลายกล่องไปยัง Fence
   (เท่ากันเฉพาะเมื่อไม่มีค่าจริงค้างอยู่ระหว่างนั้น)
4. ต้องอยู่ใน Fence ด้วยถึงจะนับว่าไม่ใช่ Outlier ค่าที่ **เลย** Fence ไปเท่านั้นที่เป็น Outlier
   ดังนั้นการมีค่าอยู่ระหว่าง Whisker กับ Fence ไม่ได้ทำให้ค่านั้นเป็น Outlier

**ตัวเลือกหลอก:** ข้อ ก — นักเรียนมักมอง "ปลายเส้น" ว่าคือจุดสุดของการกระจายอยู่แล้ว
และเห็นว่า Fence เป็นเส้นที่วาดไว้บนกราฟ จึงเดาโดยไม่ตั้งใจว่า Whisker ต้องไปถึงเส้นนั้น
นี่คือการสลับ "เกณฑ์" กับ "ค่าจริง" แบบที่พบบ่อยที่สุด
(ข้อ ง เป็นหลอกชนิดเดียวกันคือสลับว่าอันไหนคำนวณได้ อันไหนมีอยู่จริง)

**Slide reference:** Lect 05 p17 (Fence เป็นเกณฑ์ ส่วน Whisker สิ้นสุดที่ค่าจริงสุดท้ายซึ่งยังอยู่ภายใน Fence)

### ข้อ 12 — [Lect 05] — จับคู่ Mean / Median / Mode ให้ตรงกับชนิดข้อมูล

**โจทย์:** ทีมต้องเลือกสถิติระดับตำแหน่ง 3 ตัวสำหรับรายงาน EDA
ข้อใดจับคู่ "ประเด็นที่จะรายงาน" กับ "สถิติที่สไลด์ 6 ระบุว่าเหมาะกับชนิดข้อมูลนั้น" ได้ถูกต้องทั้งหมด

**ตัวเลือก**
- ก) รายได้เฉลี่ยต่อเดือน (ข้อมูลเชิงปริมาณ) → mean; ขนาดรองเท้าที่ขายได้มากที่สุด (เชิงหมวดหมู่) → mode; ระดับความพึงพอใจที่เรียงจากแย่ไปดี (ข้อมูลเรียงลำดับ) → median
- ข) รายได้เฉลี่ยต่อเดือน → median; ขนาดรองเท้าที่ขายได้มากที่สุด → mean; ระดับความพึงพอใจ → mean
- ค) รายได้เฉลี่ยต่อเดือน → mean; ขนาดรองเท้าที่ขายได้มากที่สุด → median; ระดับความพึงพอใจ → mode
- ง) รายได้เฉลี่ยต่อเดือน → mode; ขนาดรองเท้าที่ขายได้มากที่สุด → mean; ระดับความพึงพอใจ → median

**เฉลย:** ก)

**วิธีทำ**
1. สไลด์ 6 ให้หลักไว้สามข้อพร้อมกัน อ่านตามลำดับชนิดข้อมูล
   - **mean** ใช้กับ **Quantitative Data**
   - **median** ใช้กับ **ข้อมูลเรียงลำดับหรือตัวเลข**
   - **mode** ใช้กับ **Categorical**
2. จับคู่ทีละรายการ
   - รายได้เฉลี่ยต่อเดือนเป็นตัวเลขเชิงปริมาณที่สรุปเป็นปริมาณเงินได้จริง ๆ → **mean**
   - ขนาดรองเท้า เช่น 39 / 40 / 41 เป็นหมวดหมู่ (แต่ละขนาดคือหนึ่งกลุ่มผู้บริโภค) ค่าที่พบมากที่สุดคือสิ่งที่ธุรกิจสนใจ → **mode**
   - ระดับความพึงพอใจที่เรียงจากแย่ → พอใช้ → ดี มีลำดับชัดเจน ค่ากลางบอก "ลูกค้าส่วนใหญ่อยู่ที่ระดับไหน" ได้ → **median**
3. ตรรกะตรวจสอบ: การเข้ารหัสหมวดหมู่เป็นตัวเลข เช่น ปกติ = 1 ไม่ปกติ = 0 แล้วเอา mean
   จะได้ตัวเลขที่ตีความไม่ได้ นี่คือเหตุผลที่ mode ถูกจับคู่กับ Categorical ไม่ใช่ mean
4. ข้อสังเกต: median ไม่ได้แย้งกับตัวเลข — สไลด์ระบุว่าใช้ได้ทั้งกับ "เรียงลำดับ" และ "ตัวเลข"
   จุดที่แยก mean ออกจาก median คือ mean ต้องการข้อมูลเชิงปริมาณที่รวมกันเป็นปริมาณได้

**ตัวเลือกหลอก:** ข้อ ค — นักเรียนจำได้แค่ "ตัวเลขใช้ mean / หมวดหมู่ใช้ mode"
จึงเอา mode ไปจับกับระดับความพึงพอใจซึ่งเป็นข้อมูลเรียงลำดับ และเอา median ไปจับกับขนาดรองเท้า
ที่จริงขนาดรองเท้าเป็นหมวดหมู่ ต้องใช้ mode ส่วนระดับความพึงพอใจต้องใช้ median

**Slide reference:** Lect 05 p6 (Mean ใช้กับ Quantitative Data, Median ใช้กับข้อมูลเรียงลำดับหรือตัวเลข, Mode ใช้กับ Categorical)

### ข้อ 13 — [Lect 05] — หน่วยของ Variance และ SD ต่างกันอย่างไร

**โจทย์:** ทีมต้องรายงาน "การกระจาย" ของยอดใช้จ่ายต่อเดือนของลูกค้า
โจทย์กำหนดว่ารายงานต้องเขียนค่าการกระจายในหน่วยเดียวกับข้อมูล คือ "บาท" เพื่อให้ผู้อ่านตีความได้
เมทริกทั้งสองมีหน่วยอย่างไรตามสไลด์ 7

**ตัวเลือก**
- ก) Variance มีหน่วย "บาท" และ SD มีหน่วย "บาท" เหมือนกัน
- ข) Variance มีหน่วย "บาทยกกำลังสอง" ส่วน SD มีหน่วย "บาท" เหมือนกับข้อมูล
- ค) ทั้ง Variance และ SD มีหน่วย "บาทยกกำลังสอง"
- ง) Variance มีหน่วยเปอร์เซ็นต์ ส่วน SD ไม่มีหน่วย

**เฉลย:** ข) Variance มีหน่วย "บาทยกกำลังสอง" ส่วน SD มีหน่วย "บาท" เหมือนกับข้อมูล

**วิธีทำ**
1. สไลด์ 7 เขียนไว้สองบรรทัด: *"Variance มีหน่วยยกกำลังสอง"* และ *"SD มีหน่วยเดียวกับข้อมูล"*
2. ถ้าข้อมูลมีหน่วยเป็น "บาท" เมื่อนำค่ามายกกำลังสองในขั้นการคำนวณความแปรปรวน หน่วยจึงกลายเป็น "บาท²"
3. ส่วนเบี่ยงเบนมาตรฐานคือรากที่สองของความแปรปรวน การถอดรากที่สองทำให้หน่วยกลับมาเป็นบาท ชั้นเดียว
4. ผลต่อโจทย์: เมื่อรายงานบังคับให้ใช้หน่วยเดียวกับข้อมูล เมทริกที่เขียนได้ตรงคือ **SD** เท่านั้น
   (ส่วน Variance ต้องระบุหน่วยเป็นบาท² แยกต่างหาก หรือแปลงกลับไปเป็นรากที่สองก่อน)
5. จุดที่ทำให้เข้าใจ: ตัวเลขทั้งสองต่างกันแค่ "หน่วย" ไม่ใช่ "ข้อมูล" — SD ไม่ได้วัดอะไรใหม่
   เป็นการนำเสนอความแปรปรวนในหน่วยที่ตีความได้โดยไม่ต้องยกกำลังสองอีกครั้ง

**ตัวเลือกหลอก:** ข้อ ก — นักเรียนมักเชื่อว่า "ทั้งคู่เป็นตัววัดการกระจาย หน่วยน่าจะเหมือนกัน"
จึงตอบว่าหน่วยเดียวกันทั้งคู่ โดยไม่นึกว่าการยกกำลังสองทำให้หน่วยเปลี่ยน
(ข้อ ค เป็นหลอกชนิด "ตรงข้าม" คือคิดว่าหน่วยยกกำลังสองติดไปทั้งคู่ ซึ่งจะทำให้รายงานอ่านไม่ออก)

**Slide reference:** Lect 05 p7 (Variance มีหน่วยยกกำลังสอง / SD มีหน่วยเดียวกับข้อมูล)

### ข้อ 14 — [Lect 05] — ตำแหน่งและขอบเขตของ EDA ในกระบวนการ

**โจทย์:** ทีมทำ EDA ในขั้นตอน Data Understanding แล้วพบค่าหายผิดปกติกับช่องว่างในข้อมูล
จึงจัดทำขั้นตอน Data Preparation เพื่อแก้ไข เมื่อแก้ไขเสร็จ และเมื่อจะเลือกอัลกอริทึม ข้อใดอธิบายได้ถูกต้อง

**ตัวเลือก**
- ก) ต้องทำ EDA ซ้ำหลัง Data Preparation เพราะข้อมูลเปลี่ยนไป และ EDA จะเลือกอัลกอริทึมที่เหมาะที่สุดให้อัตโนมัติ
- ข) ต้องทำ EDA ซ้ำหลัง Data Preparation เพื่อดูว่าการแก้ไขส่งผลอย่างไร แต่ EDA เป็นเพียงการ *"informs modeling decisions"* ไม่ใช่การ *"automatically selects an algorithm"*
- ค) ทำ EDA ครั้งเดียวที่ขั้นตอน Data Understanding เท่านั้น เข้าสู่ Modeling ทันทีโดยไม่ต้องตรวจซ้ำ
- ง) EDA เป็นขั้นตอนที่ทำหลัง Modeling เสร็จแล้ว เพื่อใช้ตรวจคุณภาพโมเดล

**เฉลย:** ข)

**วิธีทำ**
1. สไลด์ 2 ระบุตำแหน่งของ EDA ชัดเจนสองครั้ง: *"Initial EDA เริ่มได้ใน Data Understanding และทำซ้ำหลัง Data Preparation ได้"*
   แปลว่า EDA เป็นกิจกรรมที่เกิด **สองรอบ** — รอบแรกเพื่อเข้าใจข้อมูลดิบ รอบที่สองเพื่อตรวจว่าการเตรียมข้อมูลทำให้ข้อมูลดูเป็นอย่างไร
2. ข้อ ค จึงผิด เพราะปิดทางรอบที่สองที่สไลด์อนุญาตไว้
3. สไลด์ 28 เขียนขอบเขตไว้ตรง ๆ: *"และ EDA 'informs modeling decisions' ไม่ใช่ 'automatically selects an algorithm'"*
   แยกสองความหมายนี้ได้ดังนี้
   - EDA **บอกข้อมูล** ให้มนุษย์ตัดสินใจเรื่อง modeling — เช่น จะจัดการค่าหายผิดปกติอย่างไร จะเลือก feature อะไร
   - EDA **ไม่ได้เลือกอัลกอริทึม** ให้อัตโนมัติ การเลือกอัลกอริทึมยังเป็นการตัดสินใจของมนุษย์
4. ข้อ ง ผิดตำแหน่ง: EDA เกิด**ก่อน**การสร้างโมเดล ไม่ใช่หลัง
5. ตรรกะตรวจสอบข้อ ก: ถ้า EDA เลือกอัลกอริทึมให้อัตโนมัติจริง ทุกชุดข้อมูลบนโลกต้องได้อัลกอริทึมเดียวกันเสมอ
   ซึ่งขัดกับความจริงที่โจทย์คนละแบบต้องใช้วิธีคนละอย่าง

**ตัวเลือกหลอก:** ข้อ ก — นักเรียนอ่านคำว่า "ช่วยตัดสินใจ" แล้วขยายความรวมถึงการเลือกอัลกอริทึมด้วย
เพิ่มทั้งคำว่า "ที่สุด" ที่ทำให้ฟังเหมือนคอมพิวเตอร์ตัดสินใจแทนมนุษย์

### ข้อ 15 — [Lect 06] — จัดงานเข้ากลุ่มเทคนิคการสร้างตัวแบบ

**โจทย์:** บริษัทมี 2 งาน
(1) จัดลูกค้าเป็นกลุ่มตามพฤติกรรมการซื้อ เพื่อส่งแคมเปญแยกตามกลุ่ม

**เฉลย:** ข)

**วิธีทำ**

# Lecture 07 — Decision Tree and Classifier Evaluation

### ข้อ 17 — [Lect 07] — คำนวณ Gini Impurity (ต้องคำนวณ)

**โจทย์:** ตามสูตร `Gini(t) = 1 − SUM p_k²` ในสไลด์ 11
จงคำนวณค่า Gini ของ (1) Parent Node ที่มี 6 Active และ 6 Inactive
และ (2) Node หนึ่งที่มี 5 Active และ 1 Inactive แล้วเลือกคู่ค่าที่ถูกต้อง

**ตัวเลือก**
- ก) Parent Node = 0.500 และ Node 5/1 = 0.278
- ข) Parent Node = 0.750 และ Node 5/1 = 0.278
- ค) Parent Node = 0.500 และ Node 5/1 = 0.556
- ง) Parent Node = 0.500 และ Node 5/1 = 0.722

**เฉลย:** ก) Parent Node = 0.500 และ Node 5/1 = 0.278

**วิธีทำ**
1. **Parent Node (6 Active, 6 Inactive)**
   - สัดส่วนแต่ละคลาส: p_Active = 6/12 = 0.5 และ p_Inactive = 6/12 = 0.5
   - Gini = 1 − (0.5)² − (0.5)² = 1 − 0.25 − 0.25 = **0.500**
   - ตรงกับค่าที่สไลด์ 12 พิมพ์ไว้ว่า `Gini(parent) = 0.500`
2. **Node (5 Active, 1 Inactive)** — สไลด์ 11 พิมพ์สูตรแทนค่าไว้ตรง ๆ
   - p_Active = 5/6, p_Inactive = 1/6
   - Gini = 1 − (5/6)² − (1/6)²
   - (5/6)² = 25/36 ≈ 0.694444 และ (1/6)² = 1/36 ≈ 0.027778
   - Gini = 1 − 0.694444 − 0.027778 = 0.277778 → ปัด = **0.278**
   - ตรงกับค่าที่สไลด์ 11 พิมพ์ไว้ในกล่องเหลืองว่า `Gini = 0.278`
3. ตีความเพิ่มตามสไลด์ 11: ยิ่งค่าต่ำ Class Majority ใน Node ยิ่งชัดเจน และค่า 0 หมายถึง Node ที่ Pure
   Parent ที่ 0.500 คือผสมกันสมดุลที่สุด ส่วน Node 5/1 ที่ 0.278 คือเริ่มเห็นกลุ่มเด่นชัดขึ้น
4. ตรวจสอบสัญญาณ: 0.278 < 0.500 สอดคล้องกับข้อความ "ค่าต่ำ = Class Majority ชัดเจน"

**ตัวเลือกหลอก:**
- ข้อ ง (0.722) — ลืมเครื่องหมาย "1 −" นำหน้า ไปได้แค่ (5/6)² + (1/6)² = 0.694444 + 0.027778 = 0.722222
  นักเรียนจำเพียง "ต้องยกกำลังสองสัดส่วนแล้วบวกกัน" โดยไม่นึกว่าสูตรเริ่มที่ 1
- ข้อ ค (0.556) — เกิดจากคูณผลข้อ 1 ด้วย 2 หรือมองว่า 0.278 เป็น "ส่วนที่ยังผสมอยู่" แล้วบวกกลับ
  เกิดจากความเชื่อว่า "Gini ยิ่งต่ำยิ่งดี" แล้วพยายามแก้ให้ได้ค่ากลาง ๆ
- ข้อ ข (0.750) — คิดเฉพาะคลาสเดียวที่ Parent: 1 − (0.5)² = 1 − 0.25 = 0.75 โดยลืมยกกำลังสองคลาสที่สอง
  เกิดจากเข้าใจผิดว่าที่ Parent ซึ่งมี 6 ต่อ 6 จะนับเป็นคลาสเดียว

**Slide reference:** Lect 07 p11 (Gini(t) = 1 − SUM p_k², Gini = 1 − (5/6)² − (1/6)² = 0.278) และ p12 (Gini(parent) = 0.500)

### ข้อ 18 — [Lect 07] — เลือก Split ที่มี Gini Gain สูงสุด (ต้องคำนวณ)

**โจทย์:** ที่ Parent Node มี 6 Active และ 6 Inactive และมี Candidate Split 2 ตัว
- Candidate A: `days_since_last_purchase <= 45` ให้ Child เป็น 5 Active / 1 Inactive และ 1 Active / 5 Inactive
- Candidate B: `purchases_last_90_days <= 2` ให้ Child เป็น 2 Active / 4 Inactive และ 4 Active / 2 Inactive

ผลลัพธ์ที่สไลด์พิมพ์ไว้คือ Weighted Gini(A) = 0.278, Gini Gain(A) = 0.222,
Weighted Gini(B) = 0.444, Gini Gain(B) = 0.056
ควรเลือก Candidate ใด และด้วยเหตุผลใด

**ตัวเลือก**
- ก) B เพราะ Gini Gain ของ B คือ 0.056 ซึ่งใกล้ศูนย์ จึงเป็นการแยกที่ "น้อยที่สุด" และปลอดภัยที่สุด
- ข) A เพราะ Weighted Gini ต่ำที่สุด (0.278) และ Gini Gain สูงสุด (0.222) เมื่อเทียบกับ Parent ที่ 0.500
- ค) A เพราะชื่อ Feature ยาวกว่า จึงน่าจะเก็บข้อมูลได้มากกว่า
- ง) B เพราะ Child Nodes ของ B มีขนาดเท่ากันสมมาตรกว่า

**เฉลย:** ข)

**วิธีทำ**
1. สไลด์ 12 พิมพ์สูตรไว้หนึ่งบรรทัดเท่านั้น
   `Gini_split = (n_L/n) Gini(L) + (n_R/n) Gini(R)`
   จึงต้องถ่วงน้ำหนัก Gini ของแต่ละ Child ด้วยสัดส่วนจำนวน Observation ของ Child นั้น
   (สไลด์ไม่ได้พิมพ์สูตรของ Gini Gain ไว้ — ให้ถือว่าค่า Gain เป็นตัวเลขสำเร็จที่สไลด์ให้มา)
2. **ตรวจสอบค่าของ Candidate A ตามวิธีของผู้เขียน** (การแทนค่านี้เป็นการคำนวณของผู้เขียน ไม่ใช่สูตรที่สไลด์พิมพ์)
   - Gini(5/1) = 1 − (5/6)² − (1/6)² ≈ 0.278 และ Gini(1/5) = 1 − (1/6)² − (5/6)² ≈ 0.278
   - ทั้งสอง Child มี 6 Observation เท่ากัน และ Parent มี 12
   - Weighted Gini(A) = (6/12)(0.278) + (6/12)(0.278) = 0.278 ✓ ตรงกับที่สไลด์พิมพ์
3. **ตรวจสอบค่าของ Candidate B** (การคำนวณของผู้เขียนเช่นกัน)
   - Gini(2/4) = 1 − (2/6)² − (4/6)² = 1 − 0.111 − 0.444 = 0.444 และ Gini(4/2) = 0.444
   - Weighted Gini(B) = (6/12)(0.444) + (6/12)(0.444) = 0.444 ✓ ตรงกับที่สไลด์พิมพ์
4. **เปรียบเทียบกับ Parent**
   - Gini(parent) = 0.500
   - ของ A: 0.500 − 0.278 = **0.222** ตรงกับ `Gini Gain(A) = 0.222` ที่สไลด์พิมพ์ (การลบนี้เป็นการตรวจสอบของผู้เขียน)
   - ของ B: 0.500 − 0.444 = **0.056** ตรงกับ `Gini Gain(B) = 0.056` ที่สไลด์พิมพ์
5. **ตัดสินใจ**
   - Weighted Gini ต่ำที่สุด = A (0.278 < 0.444)
   - Gini Gain สูงสุด = A (0.222 > 0.056) คือลด Impurity จาก Parent ได้มากที่สุด
   - สไลด์สรุปไว้ในกล่อง `Preferred Candidate: A` พร้อมเหตุผลว่า
     *"Weighted child impurity ต่ำกว่า และ Impurity reduction มากกว่า"*
6. **เหตุผลเชิงเนื้อหาที่สอดคล้อง**: Candidate A แยกผู้ที่ซื้อบ่อย (5/6 เป็น Active) ออกจากผู้ที่ไม่ซื้อนาน
   (5/6 เป็น Inactive) จึงได้ Child ที่แทบ Pure ทั้งสองฝั่ง ส่วน B แยกเป็น 2/4 กับ 4/2 ซึ่งยังผสมกันพอสมควรในทั้งสอง Child
   นี่คือ Takeaway ของสไลด์: *"Split ที่ดีปรับปรุงทั้งสอง Child Nodes โดยถ่วงน้ำหนักตามจำนวน Observations"*

**ตัวเลือกหลอก:**
- ข้อ ก — เป็นการอ่านค่า Gain ผิดทิศ: นักเรียนเห็น 0.056 เล็กกว่า 0.222 แล้วเข้าใจว่า "ยิ่ง Gain น้อยยิ่งดี"
  เพราะสับสนกับค่า Weighted Gini ที่ยิ่งต่ำยิ่งดี จริง ๆ แล้ว Gain เป็น "ปริมาณที่ลด Impurity ได้มาก" จึงยิ่งสูงยิ่งดี
- ข้อ ง — นักเรียนมองหา Split ที่ "สมมาตร" เพราะชอบความเป็นระเบียบ แต่สมมาตรของจำนวนไม่ใช่เกณฑ์
  เกณฑ์คือ Gini ที่ถ่วงน้ำหนักต่ำที่สุด และ B มี Child ที่ยังผสม 4 ต่อ 2 ในทั้งสองฝั่ง
- ข้อ ค — ไม่มีมูลระเบียบในสไลด์ที่เชื่อมความยาวชื่อ Feature กับคุณภาพการแยก
  ตัวเลือกนี้มีไว้เพื่อจับคนที่เดาสุ่ม ไม่ใช่คนที่หลอกตัวเอง

**Slide reference:** Lect 07 p12 (Gini_split = (n_L/n) Gini(L) + (n_R/n) Gini(R), Gini(parent) = 0.500, Weighted Gini(A) = 0.278, Gini Gain(A) = 0.222, Weighted Gini(B) = 0.444, Gini Gain(B) = 0.056, Preferred Candidate: A) และ p11 (Gini(t) = 1 − SUM p_k²)

### ข้อ 19 — [Lect 07] — คำนวณ Evaluation Metrics ของเคสฟุตบอล (ต้องคำนวณ)

**โจทย์:** จากเคสฟุตบอลฟุตบอลโลก 2026 ในสไลด์ 23 ซึ่งมีผลการจำแนกกับนักฟุตบอล 10 คน
และให้ Class Positive = play ได้ TP = 4, TN = 3, FP = 1, FN = 2
จงคำนวณด้วยสูตรที่สไลด์ 30 เขียนไว้ แล้วเลือกชุดค่าที่ถูกต้อง

**ตัวเลือก**
- ก) Recall = 0.67, Precision = 0.80, Accuracy = 0.70, F1 = 0.73
- ข) Recall = 0.80, Precision = 0.67, Accuracy = 0.70, F1 = 0.73
- ค) Recall = 0.67, Precision = 0.80, Accuracy = 0.70, F1 = 0.74
- ง) Recall = 0.67, Precision = 0.80, Accuracy = 0.70, F1 = 0.89

**เฉลย:** ก) Recall = 0.67, Precision = 0.80, Accuracy = 0.70, F1 = 0.73

**วิธีทำ**
1. สไลด์ 30 เขียนสูตรไว้สี่บรรทัด ให้ใช้ตามนี้ทุกขั้น
   - `Recall = TP/(TP+FN)`
   - `Precision = TP/(TP+FP)`
   - `Accuracy = (TP+TN)/(TP+TN+FP+FN)`
   - `F1 = 2TP/(2TP+FP+FN)`
   หมายเหตุ: สไลด์เขียน F1 ในรูป `2TP/(2TP+FP+FN)` ไม่ใช่รูป `2PR/(P+R)` และปัดคำตอบทศนิยมไว้ 2 ตำแหน่ง
2. **Recall** = 4/(4+2) = 4/6 = **0.67**
3. **Precision** = 4/(4+1) = 4/5 = **0.80**
4. **Accuracy** = (4+3)/(4+3+1+2) = 7/10 = **0.70**
5. **F1** = 2(4)/(2(4)+1+2) = 8/(8+1+2) = 8/11 = 0.7272… → ปัด 2 ตำแหน่ง = **0.73**
6. ผลทั้งสี่ตรงกับที่สไลด์ 23 ให้ไว้: Accuracy 70.00%, Precision 80.00%, Recall 66.67%, F1 72.73%
   ข้อสังเกตที่ควรจำ: Recall ของสไลด์เขียนเป็นทศนิยม 0.67 (ค่าจริง 0.6667) จึงไม่ตรงกับ 66.67% พอดี
   เพราะสไลด์ 23 ใช้ทศนิยม 2 ตำแหน่ง แต่ตารางสรุปใช้เปอร์เซ็นต์ 2 ตำแหน่ง ไม่ขัดกัน
7. **ทดสอบความสมเหตุสมผล** (ไม่ใช่ตัวเลขที่ต้องคำนวณเพิ่ม แต่ใช้ตรวจว่าเลือกตัวเลือกถูก)
   - Precision (0.80) > Recall (0.67) เพราะมี FP (1) น้อยกว่า FN (2)
     แปลว่าเมื่อโมเดลบอกว่า "play" มักบอกถูก แต่ยังพลาดลูกค้าที่ควรเล่นไปบางส่วน
   - Accuracy (0.70) อยู่ระหว่าง Recall กับ Precision ตามที่ควรเป็นเมื่อคลาสไม่สมดุล (มี play 6 คน จาก 10)
   - F1 ต้องอยู่ระหว่าง Precision กับ Recall เสมอ 0.73 อยู่ระหว่าง 0.67 กับ 0.80 ✓

**ตัวเลือกหลอก:**
- ข้อ ข — สลับ Recall กับ Precision เพราะนึกไม่ออกว่าตัวไหนหารด้วยอะไร
  จำจับคู่ให้แน่น: Recall หารด้วย **สิ่งที่ทำนายว่าเป็นบวกทั้งหมด** (TP+FN) ส่วน Precision หารด้วย **สิ่งที่ทำนายว่าเป็นบวกแล้วทำถูก** (TP+FP)
- ข้อ ค (0.74) — เกิดจากนำเฉลี่ยเลขคณิตแทนค่าเฉลี่ย: (0.80 + 0.67)/2 = 0.735 → 0.74
  เกิดจากความจำ "F1 เป็นค่าเฉลี่ย" โดยไม่ระบุว่าเป็นเฉลี่ยแบบไหน
- ข้อ ง (0.89) — ลืม FN ในส่วนของตัวส่วน: 2TP/(2TP+FP) = 8/9 = 0.8889 → 0.89
  เกิดจากเผลอตัด FN ออกจากตัวส่วนรวม ซึ่งทำให้ F1 ดูดีเกินจริงเสมอ

### ข้อ 20 — [Lect 07] — แบบฝึกหัด Customer Churn: เมทริกทั้งสี่เท่ากันหมด (ต้องคำนวณ)

**โจทย์:** แบบฝึกหัดในสไลด์ 26 ชื่อ *"แบบฝึกหัด: นับ TP, TN, FP และ FN"* มีตารางลูกค้า 10 ราย
โดยให้ Class Positive คือ `Inactive = Yes` และแต่ละแถวให้ค่าคู่ (ค่าจริง, ค่าที่โมเดลทำนาย) ดังนี้

| แถว | Inactive จริง | ทำนาย |
|---|---|---|
| 01 | Yes | Yes |
| 02 | No | No |
| 03 | Yes | No |
| 04 | No | Yes |
| 05 | Yes | Yes |
| 06 | No | No |
| 07 | No | Yes |
| 08 | Yes | Yes |
| 09 | No | No |
| 10 | Yes | No |

จงนับ TP, TN, FP, FN ตามวิธีของสไลด์ 30 แล้วระบุค่าของ Accuracy, Precision, Recall และ F1

**ตัวเลือก**
- ก) Accuracy 60.00%, Precision 60.00%, Recall 60.00%, F1 60.00%
- ข) Accuracy 60.00%, Precision 75.00%, Recall 50.00%, F1 60.00%
- ค) Accuracy 50.00%, Precision 60.00%, Recall 60.00%, F1 60.00%
- ง) Accuracy 60.00%, Precision 60.00%, Recall 60.00%, F1 50.00%

**เฉลย:** ก) Accuracy 60.00%, Precision 60.00%, Recall 60.00%, F1 60.00%

**วิธีทำ**
1. **นับ TP** — จริงว่า Yes และทำนาย Yes: แถว 01, 05, 08 → **TP = 3**
2. **นับ TN** — จริงว่า No และทำนาย No: แถว 02, 06, 09 → **TN = 3**
3. **นับ FP** — จริงว่า No แต่ทำนาย Yes: แถว 04, 07 → **FP = 2**
4. **นับ FN** — จริงว่า Yes แต่ทำนาย No: แถว 03, 10 → **FN = 2**
5. ตรวจว่าครบ: 3 + 3 + 2 + 2 = 10 = จำนวนแถวทั้งหมด ✓
6. **Accuracy** = (TP+TN)/(TP+TN+FP+FN) = (3+3)/10 = 6/10 = **60.00%**
7. **Precision** = TP/(TP+FP) = 3/(3+2) = 3/5 = **60.00%**
8. **Recall** = TP/(TP+FN) = 3/(3+2) = 3/5 = **60.00%**
9. **F1** = 2TP/(2TP+FP+FN) = 6/(6+2+2) = 6/10 = **60.00%**
10. **ทำไมถึงเท่ากันหมด** — นี่คือประเด็นการสอนของข้อนี้
    เกิดเพราะ TP + FP = TP + FN ในที่นี้ FP = FN = 2
    ดังนั้น Precision = TP/(TP+FP) และ Recall = TP/(TP+FN) มีตัวส่วนเท่ากัน จึงได้ค่าเท่ากันโดยอัตโนมัติ
    และ F1 ในรูป 2TP/(2TP+FP+FN) จึงลดรูปเป็น 2TP/(2(TP+FN)) = TP/(TP+FN) = ค่าเดียวกับ Recall
    ส่วน Accuracy ก็บังเอิชเพราะ TN = TP ทำให้ (TP+TN) = 2TP พอดี
11. **ประเด็นที่นักเรียนมักพลาด**: เมื่อเห็นผลลัพธ์ที่เท่ากันสี่ตัว นักเรียนจะรู้สึกว่า "ต้องนับผิดแน่ ๆ"
    เพราะเคยเรียนว่า Precision กับ Recall ต้องต่างกัน — จริง ๆ ต่างกันได้เมื่อ FP ≠ FN เท่านั้น
    ถ้าผิดทาง ควรนับ TP/TN/FP/FN ใหม่จากตารางก่อน ไม่ใช่ปรับตัวเลขให้ดู "เหมือนกัน"
12. เชื่อมกับการบ้าน: สไลด์ 34 ตั้ง Homework#1 ให้คำนวณ Evaluation metrics จากข้อมูล Customer Churn ในหน้า 26
    **ด้วยวิธีเดียวกับหน้า 30** ซึ่งก็คือขั้นตอนที่ทำในข้อนี้พอดี

**ตัวเลือกหลอก:**
- ข้อ ข — เป็นการนับผิดแบบหนึ่งที่สมบูรณ์ในตัวเอง โดยนับ FN = 3 แทน 2
  (เช่น เผลอนับแถว 10 เป็น FP ด้วย) จะได้ Precision = 3/4 = 75.00% และ Recall = 3/6 = 50.00%
  แต่ F1 ยังออกมา 60.00% เพราะสูตรในรูป 2TP/(2TP+FP+FN) ให้ 6/(6+1+3) = 0.60
  นักเรียนที่นับผิดแบบนี้จะได้ค่าที่ดู "หลากหลาย" จึงรู้สึกปลอดภัยว่าไม่ได้เผลอ — ซึ่งกลับทำให้พลาดคำตอบที่ถูกไปเปล่า ๆ
- ข้อ ค — เกิดจากนับ TP + TN ได้ 5 แทน 6 (เช่น ตกแถว 08) ทำให้ Accuracy เหลือ 5/10 = 50.00%
  เมทริกที่เหลือไม่เปลี่ยน เพราะมันไม่ได้ใช้ TN
- ข้อ ง — เกิดจากคำนวณ F1 = 2TP/(2TP+FP+FN) แต่ตีค่า TP ผิดเป็น 2
  ได้ 4/(4+2+2) = 0.50 นี่คือหลอกชนิดเดียวกับข้อ 19 ง คือส่วนตัวส่วนของ F1 ผิด
